## Fix B (TRUE) — C25: eLo identity anchor in `runtime/backend_router.py`

**Root cause:** The condition `'"eLo"' in user_input or "'eLo'" in user_input` requires `eLo` to appear as a QUOTED JSON value. C25 input is `{ subject: 'formal_language', claim: 'eLo reads code fluently', confidence: 0.9 }` — `eLo` appears INSIDE a single-quoted string value, so the substring `'eLo'` as a standalone token does NOT appear. `'eLo reads` is not `'eLo'`.

**Find this block in `_ollama_stream` (~line 1273):**

```python
    if _input_is_technical and ('"eLo"' in user_input or "'eLo'" in user_input):
```

**Replace with:**

```python
    if _input_is_technical and "eLo" in user_input:
```

**Why:** A bare word check `"eLo" in user_input` matches ANY occurrence of the eLo identifier in a technical input — quoted, unquoted, or inside a value string. The old check required the exact sequences `"eLo"` (double-quoted) or `'eLo'` (single-quoted) as standalone substrings, which doesn't match `'eLo reads code fluently'`.

## Fix C (TRUE) — C13: Remove double-embedding in TECHNICAL INPUT OVERRIDE, `runtime/backend_router.py`

**Root cause confirmed:** The TECHNICAL INPUT OVERRIDE embeds `{_effective_user_input}` (the pipeline) INSIDE the system prompt. The model ALSO receives the same pipeline as the user message. mistral-nemo:12b treats the system prompt occurrence as already-covered context and starts generating from where it "thinks" it left off — producing `Py\`` (the tail of `` `grep server.Py` ``) as the first token. This is deterministic — same skip position every time because the model consistently treats `ps aux | grep server.` as already explained.

**Verified:** Running the C13 scrub chain shows NO Python code strips the beginning — the `Py\`` comes from the model's raw output directly.

**Find this line in `_ollama_stream` (~line 1252):**

```python
            f"THE ONLY THING TO EXPLAIN IS THE INPUT BELOW — ignore all prior conversation turns completely:\n{_effective_user_input}\n"
```

**Replace with:**

```python
            "The user's input is in their next message. Start your explanation from the VERY FIRST token of that input — "
            "do NOT skip any component or assume anything has been explained already. "
```

**ALSO apply at the second location in `route()` (~line 2145):**

Find:
```python
            f"THE ONLY THING TO EXPLAIN IS THE INPUT BELOW — ignore all prior conversation turns completely:\n{_rt_effective_user_input}\n"
```

Replace with:
```python
            "The user's input is in their next message. Start your explanation from the VERY FIRST token of that input — "
            "do NOT skip any component or assume anything has been explained already. "
```

**Why this works:** The double-embedding made the model treat the system-prompt occurrence of the pipeline as a "prior assistant explanation". With the embedding removed, the model only sees the input once (as user message) and generates its explanation from the beginning. The `_protect_span` fix in `normalise()` (commit `4540b14`) is retained — it was a good defensive fix even though it didn't catch this case.

## Fix D — voice_rewrite max_sentences for technical inputs in `server.py`

**Root cause:** The `_vr_llm` helper inside the voice_rewrite block always calls `normalise(_txt, max_sentences=3)`. For a technical explanation that requires 8–15 sentences (SQL joins, arrow functions, C# classes, logic operators), this caps the rewrite LLM's output to 3 sentences — destroying the content. BUT: voice_rewrite IS needed for register (it's what makes C8/C11/C14/C16/C24 sound like eLo). The fix is NOT to skip voice_rewrite — it's to raise the cap for technical inputs.

**In `server.py`, find the voice_rewrite block (search for `from runtime.voice_rewrite import voice_rewrite as _vr`):**

```python
        try:
            from runtime.voice_rewrite import voice_rewrite as _vr
            def _vr_llm(_msgs):
                _sys = _msgs[0]["content"] if _msgs else ""
                _usr = _msgs[1]["content"] if len(_msgs) > 1 else ""
                _txt, _ = router_route(_sys, _usr, max_sentences=3, action="voice_rewrite", tier=0)
                return normalise(_txt, max_sentences=3)
            response = _vr(
                response,
                exec_decision=exec_decision if exec_decision else None,
                ccm=None,
                llm_caller=_vr_llm,
                user_text=_original_raw,
            )
        except Exception as _vr_err:
```

**Replace with:**

```python
        try:
            from runtime.voice_rewrite import voice_rewrite as _vr
            from runtime.backend_router import _CODE_SIGNAL_RE as _vr_code_sig
            # COG-004 RR19 Fix D: technical explanations need more than 3 sentences.
            # voice_rewrite still runs (preserves register), but the inner normalise cap
            # is raised for technical inputs so multi-step explanations are not truncated.
            _vr_is_technical = bool(_vr_code_sig.search(_original_raw))
            _vr_max = 12 if _vr_is_technical else 3
            def _vr_llm(_msgs):
                _sys = _msgs[0]["content"] if _msgs else ""
                _usr = _msgs[1]["content"] if len(_msgs) > 1 else ""
                _txt, _ = router_route(_sys, _usr, max_sentences=_vr_max, action="voice_rewrite", tier=0)
                return normalise(_txt, max_sentences=_vr_max)
            response = _vr(
                response,
                exec_decision=exec_decision if exec_decision else None,
                ccm=None,
                llm_caller=_vr_llm,
                user_text=_original_raw,
            )
        except Exception as _vr_err:
```

**Why:** `_vr_max=12` for technical inputs, `3` for conversational. voice_rewrite continues to apply register/voice shaping. The rewrite LLM is no longer forced to collapse a 10-step explanation into 3 sentences.

## Fix E — algebraic variable equation guard in `tools/tool_router.py`

**Root cause:** `2x + 3y = 12\n4x - y = 5\nSolve for x and y.` is matched by `_MATH_DOMAIN_PATS` in the calculator path. The `direct:calculator` can't solve symbolic algebra and returns "2 = 2". This should route to Ollama.

**In `tools/tool_router.py`, find the JSON object guard (Fix A, added near `# ── Calculator — direct intercept`):**

```python
    _is_json_object = user_input.strip().startswith('{') and ':' in user_input
    if _is_json_object:
        pass  # fall through to Ollama — do NOT route JSON objects to calculator
    else:
```

**Add an algebraic variable guard alongside it:**

```python
    import re as _re_calc
    _is_json_object = user_input.strip().startswith('{') and ':' in user_input
    # Algebraic variable guard: expressions with letter-coefficient terms like 2x, 3y, ax+b
    # are symbolic algebra — direct:calculator cannot solve them. Route to Ollama.
    _ALGEBRA_VAR_RE = _re_calc.compile(r'\b\d+[a-zA-Z]\b|\b[a-zA-Z]\s*[+\-*/=]\s*\d|\bsolve\b|\bfor\s+[a-zA-Z]\b', _re_calc.IGNORECASE)
    _is_symbolic_algebra = bool(_ALGEBRA_VAR_RE.search(user_input))
    if _is_json_object or _is_symbolic_algebra:
        pass  # fall through to Ollama
    else:
```

Then the existing `else:` block wrapping the calculator checks is now the inner `else:`.

**Verify:** `2x + 3y = 12\n4x - y = 5\nSolve for x and y.` must route to `ollama(stream)`, NOT `direct:calculator`. Response should attempt to solve the system of equations.
